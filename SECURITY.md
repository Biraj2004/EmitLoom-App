# Security policy

## Supported reports

Report security issues in the latest published EmitLoom release or on the `main` branch. For an older build, include its exact version and indicate whether you checked the current release.

## Report a vulnerability privately

1. Open [EmitLoom Security Advisories](https://github.com/Biraj2004/EmitLoom-App/security/advisories) and select **Report a vulnerability** if available.
2. If the button is unavailable, [open a GitHub issue](https://github.com/Biraj2004/EmitLoom-App/issues/new) asking a maintainer for a private contact channel. Keep the issue to that request. Share the vulnerability details only through the private channel.

Include the EmitLoom version or commit, Android version, affected controller model and firmware when relevant, the observed impact, and enough information for maintainers to reproduce the issue safely. Redact Bluetooth addresses, credentials, personal data, and unrelated logs. Test only devices and environments you own or have permission to use.

Give maintainers an opportunity to investigate and coordinate disclosure before making technical details public. Use [GitHub Issues](https://github.com/Biraj2004/EmitLoom-App/issues) for ordinary bugs and compatibility reports.

[GitHub's private reporting guide](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately)
